# 대화 판단 개편 v0.2

적용일: 2026-11-06. 기존 API·DB·화면 계약은 유지한다.

## 실행 흐름

세션 복원 → 현재 요청을 JSON 행동으로 판단 → 서버가 대상·변경 조건 검증 → 필요한 Tool 실행 또는 추가 질문 → 검증된 결과 구성 → 상태 저장·SSE 반환.

LLM은 추천·옵션 조회·설명·견적·비교·판매 순위·추가 답변·확인 질문 중 한 행동을 제안한다. 상품 대상을 사용자 원문으로 전달하고, 서버가 실제 상품명·최신 목록 순번·SKU와 연결한다. 현재 입력과 과거 대화를 구분한다. 금액·재고는 기존 DB 접근 모듈과 Python Tool이 처리한다.

특정 문구마다 다른 Tool로 덮어쓰던 분기는 실행 경로에서 제거했다. 기존 `interpretation.py`에서는 상품명·순번·금액 등의 값 해석만 사용한다. 답변 전체를 모델에 다시 출력시키던 마지막 호출도 제거했다. 안내문은 검증 결과로 구성하고, 설명서 검색과 관련 근거 선택은 기존 RAG 경로를 사용한다. 상담 안내서용 별도 Vector DB는 추가하지 않았다.

## 상태와 후속 답변

- `task.intent`, `task.waiting_for`에 진행 중 작업과 부족한 항목을 기록한다.
- 선택 상품·SKU·수량과 구매 조건은 최근 대화 5쌍·표시 목록 2회분과 별도로 저장한다.
- 수량 답변은 현재 SKU를 유지하고 수량만 갱신한다. `2개`, `두 개`, `2대`, `2`를 지원한다.
- `3ro`는 3개인지 확인하고, 확인 전에는 견적을 계산하거나 선택을 바꾸지 않는다. 단순한 `네`를 4개로 해석하지 않는다.
- 재고 부족이면 실제 부족 수량을 안내하고 사용자 변경을 기다린다.
- 명확한 새 요청은 새 행동으로 전환한다. 새 대상이 검증된 뒤 선택 상태를 바꾸며, 실패하면 기존 선택을 보존한다.
- `그중`은 직전 표시 목록으로 검색 범위를 제한한다. `두 번째`도 직전 표시 순서 기준이다. 모호한 `아까`는 확인한다.
- 세션 30분 만료·요청 120초·요청 중복 방지·세션별 순차 처리는 유지한다.

## 최소 JSON 예

```json
{
  "action": "quote",
  "targets": [{"reference": "두 번째 제품"}],
  "values": {"quantity": 3},
  "evidence": {"quantity": "3대"},
  "scope": "catalog",
  "scope_reference": ""
}
```

참조는 서버가 목록에 연결한다. 입력에 없는 대상이나 SKU 내부 숫자를 수량으로 사용하는 변경은 적용하지 않는다. 형식이 잘못된 모델 응답은 기존 모델 오류로 처리하고 상태를 저장하지 않는다. 형식은 맞지만 대상을 확인할 수 없으면 기존 상태를 유지하고 되묻는다.

### 검색 범위 분리

구매 조건에는 이전 결과의 상품 ID를 저장하지 않는다. 기존 세션의 `constraints.scope_product_ids`도 다음 요청에서 제거한다. 추천·판매 순위의 실행 조건은 매번 구매 조건 사본에서 만든다.

`scope=catalog`가 기본이며, 예산·용도·브랜드 등 조건 변경 후 전체 상품을 재평가한다. `scope=referenced_list`는 현재 발화의 명시적인 목록 참조인 `scope_reference`를 확인한 경우만 허용한다. 이때 상품 ID는 서버가 직전 목록에서 가져와 이번 Tool 실행에만 전달한다. 없는 목록이나 모호한 이전 목록 참조는 확인 질문으로 처리한다.

완료된 추천의 조건 변경은 재추천으로 처리한다. 실제 대기 질문의 추가 답변은 기존 작업을 이어간다. 특정 상품의 순번 선택과 추천 검색 범위는 독립적이므로 ‘두 번째 제품 견적’에 목록 검색 제한을 저장할 필요가 없다.

검증: 자동 테스트 138개 및 실제 모델 연속 입력 20개 통과. 이전 목록 한정 → 일반 촬영용 추천 → 예산 100만 원 변경 후 전체 후보 재평가와 50만 원 초과 상품 진입을 확인했다. 확대된 후보의 평가 누락을 막기 위해 5개씩 평가하고 각 상품의 점수 필드를 필수로 검증한다. 이번 실행의 예산 변경 응답은 약 23초였으며 성능 보장값은 아니다.

## 검증

`python -m pytest backend/tests -q`로 자동 검증한다. DB 통합 검증은 `RUN_DB_TESTS=1`로 실행한다.

`python -m backend.tests.smoke_planner_v2`는 실제 Qwen3 8B·DB·Tool로 다음 대화를 검증한다. 상담 DB에는 쓰지 않는다.

1. 추천 → 옵션 → SKU 견적 → 오타 → 여러 수량 표기 → 재고 부족 → 수량 변경 견적 → 설명서 장점.
2. 삼성·예산 조건 → 직전 목록의 촬영용 추천 → 두 번째 상품 3대 → SKU 선택 → 견적 → 비교 → 판매 순위.
3. 예산 50만 원 추천 → 150만 원으로 변경.

확인한 시나리오의 통과는 모든 자연어 표현의 정확도를 보장하지 않는다. 모델 교체·판단 안내 변경 시 동일 평가를 다시 실행한다.

### 2026-11-06 실행 결과

- 자동 테스트: DB 통합 검증 포함 127개 통과. 라이브러리 사용 중단 예정 경고 1건.
- 실제 Qwen3 8B·DB·Tool 평가: 위 17개 입력의 연속 대화 통과. ‘그중’은 기존 목록 밖 상품을 포함하지 않았고, 순번 견적은 최신 목록의 두 번째 상품에 연결됐다.
- 실행 중 서버의 HTTP/SSE 평가: 추천 → 두 번째 상품 3대 → SKU 선택 → 669,000원 견적 → 같은 요청 재전송 → 5대 1,115,000원 재계산 통과. 요청 재전송은 기존 결과를 반환했다. 상담 초기화 후 이전 ID 접근은 410으로 차단했다.
- 새 백엔드 이미지로 재시작 완료. 고객 화면의 API 프록시 200, 백엔드 상태 200 OK 확인.
