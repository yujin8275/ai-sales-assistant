# ABC Electronics 예외 처리 명세서

버전: 0.1 초안 / 작성일: 2026-11-05  
범위: API 입출력 명세 0.2에서 분리한 업무 상태·처리 오류·재시도 규칙. 실제 장애 주입 평가는 미실행이다.

## 1. 정상 업무 분기

| 상태 | 조건 | 출력·다음 행동 |
|---|---|---|
| NEED_INPUT | 대상·SKU·수량 등 필수 정보 부족 | 질문·missing_fields·선택지·자유 입력을 제공한다. 확실한 기존 값은 유지한다. |
| NO_MATCH | 지정 조건 안에 후보 없음 | 조건 완화를 제안하고 동의 후 재검색한다. 빈 상품 범위를 전체로 바꾸지 않는다. |
| NOT_FOUND | 상품·SKU 미등록 | 미등록 항목을 안내한다. 출시·단종·품절로 단정하지 않는다. |
| OUT_OF_STOCK | 하나 이상의 품목 재고가 요청 수량보다 부족 | 품목·가용·부족 수량과 대안을 제공한다. 정상 quote를 완료하지 않는다. |

위 상태는 대화 처리 결과이므로 HTTP 200 또는 SSE final로 반환한다. 품절 상품은 일반 추천 목록 밖에서 짧게 안내한다. 색상별·RAM별 재고를 임의 합산하지 않는다.

## 2. 할인·근거 부재

정책 없음·비활성·기간 만료·비대상은 할인 0원과 해당 사유로 안내한다. 카드사에 복수 정책이 있으면 PROMO_CONFIG_ERROR로 실패하며 임의 정책을 고르지 않는다. 문서 근거가 없으면 확인된 SQL 사양·가격은 제공하되 미확인 성능·문서 출처를 만들지 않는다.

## 3. 처리 오류 계약

| code | HTTP 시작 전 | retryable | 안내·처리 |
|---|---|---|---|
| INVALID_INPUT | 422 | false | 입력 항목을 수정하도록 안내 |
| SESSION_NOT_FOUND | 404 | false | 새 상담 생성 안내 |
| SESSION_EXPIRED | 410 | false | 새 상담에서 조건 다시 확인 |
| REQUEST_CONFLICT | 409 | false | 다른 입력에는 새 요청 ID 사용 |
| DEPENDENCY_UNAVAILABLE | 503 | true | 잠시 후 새 요청으로 재시도 안내 |
| MODEL_ERROR | 503 | true | 결과 대신 일시 오류·재요청 안내 |
| PROMO_CONFIG_ERROR | 500 | false | 할인 정책 확인 필요 안내 |
| REQUEST_TIMEOUT | 504 | true | 시간 초과·새 요청 안내 |
| REQUEST_CANCELLED | 409 | true | 이전 요청 취소·새 요청 안내 |
| INTERNAL_ERROR | 500 | true | 일시 오류·재요청 안내 |

SSE 시작 후에는 HTTP 상태를 변경하지 않는다. 같은 code를 담은 error 이벤트로 종료한다. 내부 SQL·접속 정보·오류 원문을 사용자에게 그대로 보내지 않는다. retryable은 새 요청으로 다시 시도할 수 있다는 뜻이며 무조건 성공함을 의미하지 않는다.

## 4. 자동 재시도와 제한시간

읽기 전용 DB 조회·질문 임베딩의 일시 연결 오류만 전체 120초 안에서 한 번 재시도한다. 상태 저장·설명 생성 실패는 이 규칙에 포함하지 않는다. 자동 재시도가 끝나도 실패하면 오류를 반환한다. 진행 이벤트·재시도마다 제한시간을 다시 시작하지 않는다.

## 5. 정상 결과 보존

Tool 성공 후 생성 LLM이 실패해도 정상 결과를 제공하지 않는다. 생성 실패를 템플릿 답변으로 대체하지 않는다. 실패한 턴을 완료된 추천·견적으로 저장하지 않으며 마지막 정상 목록·견적을 유지한다. 순수 /quote의 원래 계산형 안내는 생성 실패 대체가 아니라 정상 경로다.

## 6. 검증할 분기

부분 답변, 모호한 SKU, 빈 검색 범위, 일부 재고 부족, 만료 카드, 중복 카드 정책, 근거 없음, DB·임베딩 오류, 생성 실패, 120초 초과, 연결 취소, reset과 실행 완료 경합을 실제 구현 후 검증한다. 세부 테스트 결과는 ⑥에 기록한다.
