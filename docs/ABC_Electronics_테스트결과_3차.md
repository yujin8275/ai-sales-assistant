# ⑥ 테스트 케이스 및 평가 결과 — 3차

날짜: 2026-11-05 / 범위: 세션·대화 상태·LangGraph 고정 흐름·SSE

## 검증 결과

- 전체 자동 테스트 76개 통과. 기존 가격·재고 DB를 변경하지 않는 통합 테스트와 별도 상담 세션 생성/정리 테스트 포함.
- 실제 qwen2.5:3b 모델로 아래 연속 상담 성공.

| 입력/상황 | 실제 결과 | 소요시간(단회) |
|---|---|---|
| 50만원 이하 휴대폰 추천 | 5기종 추천 | 3.25초 |
| 두 번째 상품으로 3대 견적 | 9개 등록 옵션 표시, SKU 선택 질문 | 4.01초 |
| RM-15C-BK-4-128로 3대 견적 | 669,000원 | 3.93초 |
| 같은 요청 ID·문장 재전송 | 기존 669,000원 결과 재전달 | 0.01초 |
| 5대로 변경 | 같은 SKU, 1,115,000원으로 재계산 | 2.46초 |
| 새 상담 초기화 후 이전 요청 재전송 | HTTP 410, 이전 상태 사용 차단 | 통과 |

시간은 현재 노트북에서 측정한 값이며 성능 보장이 아니다.

## 자동 검증 범위

- 부분 답변은 받은 조건만 갱신, 색상 선호 없음과 미응답 구분.
- 최신 목록의 순번 연결, 최근 두 목록의 모호한 이전 참조 확인.
- 추천 대표 SKU를 모델이 제안해도 사용자 선택 없이는 확정하지 않음.
- 명시 SKU 선택 후 수량 질문·수량 변경, 다품목의 서로 다른 수량 보존.
- 같은 상담 순차 실행·진행 중 요청 중복 방지·완료 결과 재전달.
- 대기 시간을 포함한 제한시간, 작업 취소와 고아 진행 요청의 임의 재실행 차단.
- 모델 오류 시 마지막 정상 상태 보존, 정상 견적 덮어쓰기 금지.
- DB에서 최근 대화 5쌍·추천 2회 보관, 만료 시 캐시 재사용 차단.
- 초기화 후 이전 요청의 늦은 저장 차단, 동일 초기화 요청 반복.
- SSE final 한 번 반환, 캐시 재전달 시 과거 진행 이벤트 재생하지 않음.

## 수정한 실제 발견 사례

모델이 대표 SKU를 구매 확정으로 오해한 경우를 서버의 명시 SKU 검증으로 차단했다. 단순 수량 변경을 재추천으로 오해한 경우는 기존 선택과 연결하는 서버 분기로 보완했다. 각각 회귀 테스트를 추가했다.

## 남은 범위

현재 실행 방식은 단일 worker다. 다중 서버의 공유 큐, 모든 자연어 표현의 정확도, 사용자 화면의 SSE 연결 종료 동작, 장시간 부하, 자유로운 상품 설명 품질은 추가 검증이 필요하다. 최종 안내 문장은 검증된 데이터로 제한해 모델의 새로운 가격·사양 생성을 허용하지 않는다. 전체 서비스 완료 판정은 아직 하지 않는다.
