상태: 기능·후속 정책 및 실제 DB 대조 후 선택한 RAM 옵션·추천 가격 표시 정책을 반영했다. 이전 버전은 보관한다. 백엔드 구현 및 테스트 완료를 의미하지 않는다.

## 1. 서비스 범위

고객의 자연어 요청을 받아 상품 추천, 상품 상세, 상품 비교, 판매 순위, 재고 확인, 단일·여러 품목 견적, 후속 질문을 지원한다. 전체 기능을 지원 범위로 두고 순차 구현한다. 실제 주문·결제·재고 예약은 포함하지 않는다. n8n 기록·알림은 선택 확장이다.

| FR-12 | 설명서 검색 | 검증된 후보 상품 범위에서 관련 설명서를 검색하고 문서명·페이지를 반환한다. RDB 값 조회에 불필요하게 검색하지 않는다. 설명서 근거가 없더라도 DB에서 확인한 사양·가격은 제공할 수 있으며, 문서 근거가 없는 성능 설명은 하지 않는다. |

## 4. 부분 답변과 색상 처리

각 항목은 값을 아직 모르는 상태, 사용자가 지정한 상태, 사용자가 제한 없음을 밝힌 상태를 구분한다. 아무 답이 없다는 이유로 고객이 특정 옵션에 동의했다고 판단하지 않는다.

- 질문: “색상과 저장 용량은 어떻게 할까요?” → 답변: “256GB요.”: 용량만 저장한다. 추천에는 색상 제한 없이 진행할 수 있다.
- 답변: “색상은 아무거나, 256GB요.”: 용량 256GB와 색상 선호 없음을 저장한다.
- 답변: “검정색이요.”: 색상만 저장한다. 용량이 현재 처리에 필요하면 용량만 다시 묻는다.
- 답변: “잘 모르겠어요.”: 임의 옵션을 확정하지 않는다. 사용 목적에 맞는 등록 옵션을 제시해 선택을 돕는다.
- 질문 도중 명확한 새 요청이 오면 관련된 기존 확정 조건·선택 상품을 유지한 채 새 요청을 처리하고 불필요한 대기 질문은 해제한다. 의도가 모호할 때만 확인한다.

필요한 항목이 모두 채워지면 질문을 끝낸다. 추천에 불필요한 항목 때문에 같은 질문을 반복하지 않는다. 견적 단계에서는 실제 등록 SKU가 필요하다. 색상이 미지정되었거나 선호가 없으면 해당 기종·확정 용량에 실제 등록된 전체 색상 옵션과 각 SKU의 RAM·가격·재고를 보여준다. 품절 옵션도 품절로 표시하며, 고객 선택 후 SKU를 확정한다. 색상 목록을 안내한 것만으로 특정 옵션이 선택되었다고 간주하지 않는다.

## 5. 품절 안내의 구분

추천 목록은 구매 가능한 후보로 구성한다. 조건을 충족하는 품절 상품이 있으면 “A 모델은 현재 품절로 추천 목록에서 제외했습니다”처럼 별도 문장으로 안내한다. 이 문장은 추천 최대 5개의 순번에 포함하지 않는다.

상품에 다른 옵션 재고가 있으면 모델 전체를 품절이라고 부르지 않는다. 검정색 256GB만 재고가 없으면 해당 조합이 품절임을 설명한다. 재고 3대에 5대를 요청한 경우에는 품절이 아니라 2대 부족으로 안내한다.

## 6. 후속 명세에 반영할 확정 사항

### 추가 답변으로 확정한 색상 안내

사용자 선택: “전체 색상 표시”. 색상 미지정 견적 요청에는 해당 기종·용량에 실제 등록된 전체 색상과 옵션별 판매가·재고를 안내한다. 품절 색상도 표시한다. 색상별 후보 금액을 보여줄 수 있으나, 최종 견적은 고객이 구매할 옵션을 선택하고 SKU와 수량이 확정된 뒤 계산한다.

### DB 대조 후 추가 확정한 옵션과 가격 표시

- 같은 기종·색상·저장 용량에 RAM이 다른 SKU가 여러 개이면 RAM·판매가·재고를 옵션 표에 함께 표시하고 구매할 SKU를 선택받는다. 고객의 RAM 선택을 임의로 추정하지 않는다.
- 표의 열은 기종·색상·RAM GB·저장 용량 GB·SKU·판매가 원·재고 대수로 구성한다. 색상 미지정 시 전체 등록 색상 표시 정책과 함께 적용한다.
- 추천 가격은 사용자가 지정한 예산·용량·수량 등 조건을 충족하는 구매 가능 SKU 중 최저 판매가를 “○○원부터”로 표시한다. 해당 가격을 갖는 실제 SKU의 RAM·용량·색상을 함께 표시한다.
- 품절 또는 요청 수량을 충족하지 못하는 SKU의 더 낮은 가격을 대표 가격으로 사용하지 않는다. 가격은 한 SKU, 옵션은 다른 SKU에서 가져와 섞지 않는다. 추천한 대표 SKU가 견적 구매 옵션으로 자동 확정되지는 않는다.

### 견적과 추천 규칙

- 등록 판매가와 적용 가능한 카드 할인만 계산에 사용한다.
- 카드사별 정책은 하나로 고정한다. 다품목에서도 해당 정책의 대상 상품에만 할인을 적용한다. 정책 없음·만료·비활성·비대상은 할인 미적용 사유로 안내한다. 같은 카드사에 복수 정책이 있으면 데이터 설정 오류로 구분한다.
- 품목별 판매가×수량 소계에 대한 할인액을 원 단위 반올림한 뒤 품목 금액을 합산한다. 계산에는 Python Decimal의 ROUND_HALF_UP을 사용한다.
- 추천 적합성이 비슷하면 최근 3개월 판매량이 많은 순, 가격이 낮은 순을 적용한다. 기준일이 다른 판매량은 같은 기간처럼 비교하지 않는다.
- 동일 용량 옵션이 없는 제품도 용량 차이를 표시하고 바로 비교한다.

### 응답과 상태 규칙

- 설명서 근거가 없으면 검증된 DB 사양·가격만 제공하고 확인되지 않은 성능은 설명하지 않는다.
- 다품목 중 일부 재고 부족은 정상 견적 완료로 처리하지 않는다. 부족 품목·수량과 대안을 안내하고 사용자 선택 후 다시 계산한다.
- Tool 성공 후 AI 설명 생성 실패 시에도 정상 결과 대신 일시 오류를 안내한다. 마지막 정상 추천·견적은 유지한다.
- 최근 대화 5쌍과 별도로 최근 추천 목록 2회분을 유지한다. 명확한 새 요청으로 전환할 때 관련 조건·선택 상품을 보존한다.
- API는 정상 답변과 구분된 상품·견적·출처·상태 데이터를 함께 반환한다. 오류는 정상 성공 응답과 구분한다.

### 명세 완료 기준

정의한 정상·예외 테스트를 모두 통과해야 한다. 금액·SKU·재고 판정·출처 연결 오류는 허용하지 않는다. 문서 근거 부재를 정확하게 표시하거나 장애 상황에서 정해진 오류를 반환하는 것도 해당 예외 테스트의 정상 기대 동작이다. 실제 평가 결과는 구현 후 별도 기록한다.

### 후속 기술 명세에서 구체화

API 필드명·오류 코드, DB 접근 함수, 세션 저장 구조, 카드사별 중복 정책 등록 방지 방법, 용도 적합성 판정의 구체 기준과 정렬의 최종 동률 처리를 작성한다. 위에서 확정한 사용자 동작과 계산 규칙을 유지한다.

## 7. 검증할 주요 사례

아래 항목은 향후 테스트 케이스의 초안이며 실행·합격 결과가 아니다.

| ID | 상황 | 기대 결과 |
|---|---|---|
| TC-01 | 색상·용량 질문에 용량만 답변 | 용량만 반영하고 색상을 임의 확정하지 않는다. |
| TC-02 | 색상 미응답 상태에서 추천 요청 | 색상 필터 없이 추천하며 색상 때문에 추천을 중단하지 않는다. |
| TC-03 | 색상 미지정 또는 “아무 색상이나” 답변 후 견적 요청 | 해당 기종·용량의 전체 등록 색상과 각 SKU의 RAM·판매가·재고를 보여준다. 품절 옵션도 표시하고 구매 옵션 선택 후 SKU를 확정한다. |
| TC-04 | 구매 가능 후보 6개 | 최대 5개까지만 추천 가능하다고 안내하고 최대 5개까지 추천한다. |
| TC-05 | 구매 가능 후보 2개와 품절 후보 존재 | 추천은 2개만 제공하고 품절은 별도 짧게 안내한다. |
| TC-06 | 특정 SKU 재고 3대, 요청 5대 | 2대 부족으로 안내하고 정상 구매 가능으로 표시하지 않는다. |
| TC-07 | 예산 100만 원, 별도 기준 없음 | 1대 기준이라고 안내한다. |
| TC-08 | “5대 총 300만 원” | 총예산 300만 원으로 처리한다. |
| TC-09 | 카드사 미지정 견적 | 판매가 기준 견적을 제공하고 카드 할인 확인을 제안한다. |
| TC-10 | 두 번째 추천 상품 3대 후 5대로 변경 | 같은 선택 상품을 유지하고 5대 가격·재고로 재검증한다. |
| TC-11 | 서로 다른 SKU 여러 개 견적 | 품목별 수량·재고·금액을 검증하고 합산한다. |
| TC-12 | 30분 미활동 또는 새 상담 | 이전 상담 상태를 사용하지 않는다. |
| TC-13 | 견적 금액 기준 | 등록 판매가와 카드 할인으로 총액을 계산한다. |
| TC-14 | 소수 할인액이 발생하는 다수 수량 | 품목 소계 기준 할인액을 원 단위 반올림하며 1대별 반올림 후 곱하지 않는다. |
| TC-15 | 한 카드사의 정책 하나, 대상·비대상 상품 혼합 | 같은 정책을 사용하고 대상 상품만 할인한다. |
| TC-16 | 한 카드사에 정책이 두 개 등록된 잘못된 데이터 | 임의 정책 선택 없이 설정 오류로 처리한다. |
| TC-17 | 용도 적합성이 비슷한 후보 | 비교 가능한 최근 3개월 판매량, 낮은 가격 순으로 정렬한다. |
| TC-18 | 동일 용량 옵션이 없는 두 제품 비교 | 용량 차이를 표시하고 바로 비교한다. |
| TC-19 | 사양·가격 조회 성공, 문서 근거 없음 | 확인된 DB 값은 제공하고 문서에 없는 성능·출처는 만들지 않는다. |
| TC-20 | 여러 품목 중 일부만 재고 부족 | 전체 정상 견적 완료를 보류하고 사용자 선택을 기다린다. |
| TC-21 | Tool 성공 후 AI 설명 생성 실패 | 정상 상품·견적 결과 대신 일시 오류를 안내하고 다시 요청하도록 한다. |
| TC-22 | 최근 추천 2회분과 “두 번째”, 모호한 “아까” | 두 번째는 최신 목록에 연결하고 모호한 이전 목록은 확인한다. |
| TC-23 | 옵션 질문 중 배터리 비교로 명확한 요청 변경 | 관련 조건을 유지해 새 요청을 처리하고 불필요한 대기 질문은 해제한다. |
| TC-24 | 정상 API 응답 | 자연어 답변과 상품·견적·출처·상태 데이터가 일치한다. |
| TC-25 | 같은 색상·128GB에 RAM 4·6·8GB SKU가 존재 | RAM·판매가·재고가 구분된 옵션 표를 제공하고 고객이 구매 SKU를 선택한다. |
| TC-26 | 최저가 SKU가 품절이거나 요청 수량보다 재고 부족 | 조건을 충족하는 구매 가능 SKU의 가격을 “○○원부터”로 표시하고 그 SKU의 RAM·용량·색상을 함께 제공한다. |
| TC-27 | 사용자 지정 RAM·용량·색상 조건에 더 저렴한 비해당 SKU도 존재 | 지정 조건을 충족하는 SKU 안에서만 대표 최저가를 선택한다. |

## 8. 개정 내역

- 0.1: 기능 정책 14개와 색상 미지정 시 전체 색상 표시 반영.
- 0.2: 후속 명세 정책 12개 반영. 카드사별 단일 정책으로 기존 최유리 정책 선택 규칙 대체. 비교 용량 차이 즉시 안내, AI 설명 생성 실패 시 오류 응답, 추천 목록 2회분 보관, 계산 및 테스트 완료 기준 구체화.

- 0.3: 실제 DB에서 확인된 RAM별 복수 SKU에 대응해 옵션 표 선택을 명시하고, 구매 가능·조건 충족 SKU의 최저가와 실제 옵션을 함께 표시하도록 확정. 예정 검증 사례 TC-25~TC-27 추가.
