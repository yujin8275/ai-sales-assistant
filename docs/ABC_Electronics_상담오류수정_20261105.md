# 사용자 보고 상담 오류 수정

사용자가 보고한 추천 → 옵션 확인 → S26+ 색상 → 예산 상향 대화를 회귀 검증에 추가했다.

원인: 모델 결과를 구조 검증만 하고 의미 근거 없이 상태에 적용했으며, 명확한 상품·옵션 조회까지 작은 생성 모델의 의도 분류에 의존했다. 기존 테스트 통과는 전반적인 상담 정확도 검증을 의미하지 않았다.

수정:
- 상품 카탈로그의 실제 ID·기종명과 한글/영문 표기를 대조해 옵션·색상 조회 대상으로 연결.
- 만원/원 금액을 서버에서도 해석해 예산 수정값 검증.
- 사용자 발화에 근거 없는 브랜드·용도·빈 색상 조건 저장 방지.
- 기존 상태에 근거 없는 값이 있으면 최근 사용자 입력으로 점검. 기존 대화 화면의 답변을 소급 수정하지는 않음.
- 상품 색상 질문에는 해당 기종의 등록 색상과 SKU별 가격·재고 제공. 일반 추천 예산으로 상세 조회를 차단하지 않음.

실제 qwen2.5:3b + 기존 DB + HTTP 채팅 경로 결과:
1. 50만원 이하 추천 → constraints는 예산 500000 PER_UNIT만 저장.
2. Redmi 15C 옵션 확인 → RM-15C 옵션 9개, 오류 없음.
3. 갤럭시 S26+ 색상 → SAM002 옵션 12개, 블랙·코발트 바이올렛·핑크 골드·스카이 블루·실버 쉐도우·화이트 안내, 재추천 없음.
4. 예산 150만원 상향 → constraints.budget.amount=1500000으로 갱신, 임의 브랜드/용도 없음.

재현 명령: `docker compose -f compose.yaml -f deploy/compose.backend.yaml exec -T backend python -m backend.tests.smoke_reported_chat`

제한: 모든 자연어 표현에 대한 정확도를 보장하지 않는다. 사용자 문장별 회귀 사례를 늘려야 한다. 오류가 섞인 기존 대화 대신 새 상담으로 다시 확인하면 변경 동작을 명확히 볼 수 있다.
