# ABC Electronics Agent 대화 흐름 및 상태 설계서

버전: 0.1 초안 / 작성일: 2026-11-05  
범위: API 입출력 명세 0.2에서 분리한 실행·상태 규칙. 실제 저장 DDL과 구현 검증은 후속 작성한다.

## 1. 실행 흐름

세션 복원 → LLM 의도·조건 JSON 추출 → Pydantic 검증 → 필수 정보 확인 → Tool 실행 → 답변 생성·검증 → 정상 결과 저장 → final 반환 순서다. LangGraph의 고정 흐름을 사용한다. 정보 부족이면 필요한 1~2개 항목만 질문하고 NEED_INPUT을 정상 업무 결과로 저장한다.

추천은 Product 후보 조회 → Quote 후보 가격 계산 → 서버 예산 판정 → 필요 시 후보 한정 RAG → 최종 최대 5기종 순서다. 상세·비교·판매 순위는 해당 Product 함수를 호출한다. 견적은 SKU·수량이 확정된 뒤 Quote를 실행한다. 직접 API는 상담 상태를 변경하지 않는다.

## 2. 보관하는 상태

session_id, last_user_at, expires_at, 확정 조건, pending_question, 최근 대화 5쌍, 최근 추천 목록 2회분, 선택 SKU·수량, 마지막 정상 견적을 관리한다. 최근 목록은 list_id·상품 ID·대표 SKU·실제 표시 순서를 저장한다. “두 번째”는 최신 목록 기준이고 모호한 “아까”는 확인한다.

부분 답변은 받은 값만 갱신한다. 미응답과 선호 없음을 구분한다. 명확한 새 요청이 오면 관련 조건·선택을 보존하고 불필요한 대기 질문을 해제한다. 선택지 클릭도 message 문장으로 받으며 DB를 통해 SKU를 다시 확인한다.

## 3. 상태 전이

NEW → CLARIFYING → RECOMMENDED → SELECTED → QUOTED를 기본으로 한다. 모든 단계를 반드시 거칠 필요는 없다. 정보가 부족하면 CLARIFYING, 재추천은 RECOMMENDED, 견적 수정은 선택을 유지한 채 재계산한다. 설명 생성 실패 등 처리 오류는 마지막 정상 목록·견적을 덮어쓰지 않는다.

## 4. 만료와 초기화

마지막 사용자 입력 후 30분에 만료한다. 서버의 진행 이벤트나 heartbeat는 시간을 연장하지 않는다. 만료 접근은 즉시 차단한다. 저장 데이터 삭제·정리 주기와 테이블 DDL은 구현 설계에서 명시한다.

reset은 이전 상담을 종료하고 새 ID를 발급한다. 진행 중인 이전 요청이 나중에 끝나도 새 상태에 반영되지 않게 세션 유효성·버전을 저장 전에 확인한다. 만료·reset 이후 기존 캐시를 새 상담에 반환하지 않는다.

## 5. 순서와 중복

같은 세션의 서로 다른 요청은 접수 순서대로 처리한다. 각 요청은 자신의 차례에 최신 확정 상태를 읽는다. 다른 세션은 독립적으로 처리한다. 요청 전체 120초에는 순서 대기도 포함한다.

같은 session_id·request_id·입력은 한 번만 실행한다. 완료된 결과는 재전달하고 진행 중이면 같은 작업의 완료를 기다린다. 중간 progress 이벤트를 과거부터 재생하거나 끊긴 스트림 위치를 복구하지 않는다. 같은 ID에 다른 입력이면 REQUEST_CONFLICT다. 가격 갱신을 위한 새 견적은 새 request_id를 사용한다.

## 6. 연결 종료와 첫 버전 범위

자동 재접속·SSE 이벤트 재생·서버 재시작 후 작업 재개는 첫 버전 범위에서 제외한다. 연결이 끊겼다면 완료·저장된 결과가 있는 경우 같은 요청 ID로 결과만 재조회할 수 있다. 완료 전 취소된 요청은 실패로 기록하고 정상 대화 상태에 반영하지 않는다. 같은 ID 재전송 시 기록된 실패를 안내하고 실제 재실행은 새 요청 ID를 사용한다. 진행 중 요청에 대한 중복 전송은 작업을 새로 만들지 않는다.

서버 재시작으로 중단된 요청을 자동 성공 처리하지 않는다. 정해진 오류를 안내하고 사용자가 새 요청을 보낼 수 있게 한다. 세션 순서·완료 기록·초기화 경합의 구체 구현은 이 규칙을 만족하도록 작성하고 테스트한다.
